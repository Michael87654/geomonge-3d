# GeoMonge: телефон, GitHub Pages и сервер ИИ

## Что работает

После первого открытия сайта с интернетом дождитесь в «Инструменты → Установка и оффлайн» сообщения «Готово к работе без интернета». В кэше находятся сам интерфейс, Three.js, геометрический решатель, CSS, иконки и конфигурация. CDN не используются. На устройство загружается примерно 0,9 МБ несжатых ресурсов приложения; модель туда не загружается.

Без интернета работают построения, обычный текстовый разбор поддерживаемых задач, 2D/3D, символические алгоритмы, шаги, проекты, настройки и экспорт. ИИ отключается с сообщением об отсутствии сети. При восстановлении сети приложение пробует подключиться снова. При недоступном или ещё не настроенном сервере оно сообщает именно об этой причине. Интернет сам по себе не заменяет работающий сервер модели.

Проекты и наборы настроек хранятся в браузере этого устройства. Они не синхронизируются через GitHub. Для переноса используйте JSON. Очистка данных сайта или удаление браузером хранилища удаляет локальные данные и оффлайн-кэш; сохраняйте важные проекты в файлы.

## Установка: один ярлык

1. На Android откройте HTTPS-сайт в обычном Chrome, не в режиме инкогнито.
2. Дождитесь готовности оффлайн-кэша.
3. Нажмите в приложении «Установить приложение» или меню Chrome → «Установить приложение» / «Добавить на главный экран» → «Установить». Название команды зависит от Chrome.
4. Открывайте GeoMonge с появившегося ярлыка. Manifest задаёт standalone, название и иконки. Оба поворота экрана поддерживаются.
5. Проверьте на своём телефоне: включите авиарежим, закройте GeoMonge и откройте ярлык заново. Построение должно работать; ИИ сообщает об отсутствии сети.

Инструкция установки доступна внутри приложения. В новой версии появляется кнопка «Доступна новая версия — обновить» в разделе установки. Она активирует уже загруженный кэш и перезапускает приложение; проекты и настройки сохраняются. Кэш другого приложения на том же домене не удаляется. Если загрузка новой версии оборвалась, прежний кэш остаётся.

## Публикация готовой сборки (без установки Node)

В архиве `GeoMonge-3D-Pages.zip` — содержимое `dist`: готовые файлы сайта. Распакуйте архив. Загрузите **содержимое**, сохраняя папку `assets`, в корень ветки `main` репозитория `Michael87654/geomonge-3d`. Загрузки только самого ZIP недостаточно.

GitHub → репозиторий → Settings → Pages → Build and deployment → Source: **Deploy from a branch**, Branch: **main**, Folder: **/(root)** → Save. Дождитесь успешного `pages build and deployment`. Адрес: https://michael87654.github.io/geomonge-3d/ . Факт публикации проверяется отдельно; наличие репозитория ещё не означает доступность сайта.

GitHub Pages публикует статические файлы и не запускает Node/Ollama. Пути сборки относительные (`base: './'`), manifest и worker ограничены подпапкой репозитория. `.nojekyll` выключает ненужную обработку сборки.

## Исходники и автоматическая сборка

Полный проект находится в `GeoMonge-3D-PWA.zip`. Требуется Node.js 22 или новее:

```sh
npm ci
npm test
npm run build
```

Готовый сайт находится в `dist`. Автономный HTML дополнительно создаётся `npm run build:portable`; он не устанавливается как PWA и не содержит сервер ИИ.

Для публикации исходников вместо готовой сборки загрузите файлы проекта в корень репозитория, без `node_modules`, `.pnpm-store`, `.openai` и `dist`. В комплекте есть `.github/workflows/pages.yml`: тесты, сборка и публикация `dist`. В Settings → Pages выберите **GitHub Actions**. Используйте один способ публикации: либо готовые файлы из ветки, либо workflow исходников.

## Подключение ИИ: что ещё требуется

Сервер пока подготовлен, но не развёрнут. В `public/app-config.json` по умолчанию `{"aiBaseUrl":""}`. Поэтому на GitHub Pages показывается «Сервер ИИ ещё не подключён». Потребуется постоянно доступный сервер с Ollama и выбранной моделью, а также HTTPS-адрес API. Телефону нужен только браузер и интернет; дополнительный ярлык не нужен. Текст заданий передаётся выбранному серверу ИИ.

В этой версии используется Ollama с установленной на сервере моделью, а не внешний платный API. Прежний локальный запуск на компьютере через `Start-GeoMonge-AI.cmd` сохранён. Для `qwen3:4b-instruct` файл модели около 2,5 ГБ; дополнительно нужны память под контекст, процесс и операционную систему. Для планирования сервера разумно ориентироваться на 8 ГБ RAM и запас диска от 10 ГБ; фактическое потребление и скорость необходимо измерить на выбранном хостинге. CPU работает медленнее GPU, первый запрос загружает модель в память. Ограничение запроса — 3 минуты; большие условия лучше разделять. Качество распознавания не гарантируется: результат проверяет математический решатель, неподдерживаемые задачи могут потребовать ручного ввода.

### Вариант A: сервер с Docker Compose

На своём сервере с Docker и Compose распакуйте **исходники**, затем:

```sh
docker compose up -d --build
docker compose exec ollama ollama pull qwen3:4b-instruct
```

Compose поднимает Ollama во внутренней сети и API на `127.0.0.1:8080`; модель сохраняется в Docker volume `models`. Снаружи Ollama:11434 не публикуется. Настройте HTTPS reverse proxy на своём домене, направляющий запросы на `127.0.0.1:8080`. Пример Caddyfile для домена с настроенным DNS:

```caddyfile
ai.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

Замените домен своим. Проверьте `https://ваш-домен/health` и список моделей `/api/ollama/models`. Health проверяет процесс API, а не готовность модели. По умолчанию разрешён Origin `https://michael87654.github.io` (без пути репозитория); при другом владельце задайте `GEOMONGE_ALLOWED_ORIGINS` перед запуском Compose.

### Вариант B: API на Render, модель на отдельном сервере

Dockerfile содержит **только API**, не Ollama и не веса модели. Сам по себе этот контейнер не обеспечит работу ИИ. На Render создайте Web Service из репозитория **с исходниками**, Runtime Docker, Dockerfile в корне; Health Check Path `/health`. Выберите тариф самостоятельно. Автоматическое создание ресурсов и оплата в эту доработку не входят.

Environment:

| Переменная | Значение |
| --- | --- |
| `HOST` | `0.0.0.0` |
| `PORT` | порт сервиса Render (приложение читает переменную) |
| `OLLAMA_URL` | адрес вашего доступного Render сервера Ollama, например внутренний адрес в общей сети |
| `GEOMONGE_ALLOWED_ORIGINS` | `https://michael87654.github.io` |

Модель должна быть установлена на сервере Ollama заранее. `localhost` внутри Render указывает на контейнер API, а не ваш домашний компьютер. Если Ollama находится вне общей закрытой сети, обеспечьте защищённое соединение и ограничение доступа со стороны сервера. Не публикуйте незащищённый Ollama в интернет. Развёртывание модели, постоянный диск и достаточная память — отдельные требования; бесплатный API-сервис не предоставляет их автоматически.

Прокси разрешает один одновременный запрос, до 10 распознаваний в минуту на экземпляр и ограничивает тело запроса. CORS разрешает браузерный доступ с указанного Origin, но **не является авторизацией**. Для широкого публичного доступа добавьте на reverse proxy/платформе подходящую защиту от злоупотреблений. Секреты не помещайте в клиентские файлы.

### Последний шаг: связать сайт и API

1. После развёртывания проверьте `/api/ollama/models` и установку модели.
2. В исходниках измените `public/app-config.json`: `{"aiBaseUrl":"https://ваш-сервер-ии"}`.
3. Выполните `npm run build` и опубликуйте **весь новый dist**, включая `sw.js`. Конфигурация входит в версионированный кэш; простого изменения одного JSON на сервере недостаточно для уже установленных копий.
4. В установленном приложении с интернетом нажмите кнопку обновления. Откройте «Построить → Условие задачи», проверьте подключение и распознавание.
